boop · component candidates

Components boop needs that @donaldgifford/design-system 0.3.2 does not have: one new chart, four small controls that repo-guardian keeps local today, and the app switcher. Colours, fonts and sizes are the package's tokens. The markup is hand-drawn, so this is a proposal.

1. Stacked bars over time new block

For "runs by outcome" on the Estate page. The package's TrendChart draws one series and StackedBars stacks by category with no time axis. This is one column per day (or hour on a 1d range), stacked in the status tokens, with the legend and tooltip of ChartCard.

      Proposed props, after StackedBars: points (each { at, counts }), segments (key, label, colour), rangeDays for the x ticks, label, and a stackTimeTable() for the card's table view. A bucket with no runs shows a baseline tick, not a gap in the axis.

      2. Segmented control local in repo-guardian

      The range control on every page, and any two-to-five way switch. It is the package's Tabs list without panels. repo-guardian keeps it local (77 lines) because its version binds to the router; the unbound control can move, and each app keeps its own binding.

      6. App switcher new shell part

      A list of links to the other apps, shown when a deployment configures one. It sits in the sidebar header, which the package already documents as "the app switcher". Each entry is a plain link to another origin: no shared session and no calls between apps. With no list configured, the header is the plain identity it is today.

      What a deployment would configure

      The same list goes to every app. An app finds itself by id and marks that entry current. Names, subtitles and marks could instead be fixed in the package per known app, leaving only the URLs to configure; that is an open point for the design-system RFC.
